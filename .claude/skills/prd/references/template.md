## 3. 요구사항

### 기능 요구사항 (FR)

| # | 요구사항 | 안전 경계 |
|---|---------|----------|
| FR-1 | {정책 언어로. 코드 참조 금지} | — |
| FR-2 | {...} | [S-?] |

**FR 작성 규칙**
- 변수명·함수명·파일 경로·코드 표현식을 쓰지 않는다
- 이 문서만 읽고 구현할 수 있는 정밀도로 쓴다
- 안전 경계에 닿으면 조항 코드를 붙인다

### 비기능 요구사항 (NFR)

| # | 항목 | 요구사항 |
|---|------|---------|
| NFR-1 | 성능 | {예: 스캔 1회가 레이트리밋의 N% 이내} |
| NFR-2 | 비용 | {예: 후보 1건 분석의 토큰 상한} |
| NFR-3 | 신뢰성 | {예: 재시도 상한 소진 시 FAILED 로 종료하고 사람에게 넘긴다} |

## 4. 수용 기준

### FR-1: {요구사항명}

- [ ] {조건 A}일 때 {결과 B}가 발생한다
- [ ] {조건 C}일 때 {결과 D}가 발생하지 **않는다**
- [ ] 엣지케이스: {상황}에서 {처리 방침}

### FR-2: {요구사항명}

- [ ] ...

> 안전 경계에 닿는 FR 은 **"어기지 않았음"을 검증하는 항목**을 반드시 하나 이상 넣는다.
> 예: `- [ ] push 대상 원격의 소유자가 Fork 소유자와 다르면 push 가 수행되지 않는다 [S-1]`

### 대상 저장소 규약 영향

- `RepositoryPolicy` 의 어떤 항목을 읽는가: {sign-off / 이슈 참조 / 테스트 필수 / AI 기여 허용 여부 / 빌드 명령}
