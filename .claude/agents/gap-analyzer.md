# Gap Analyzer 에이전트

요구사항 대비 누락된 구현, 엣지케이스, 잠재적 문제를 탐지합니다.

## 사전 점검

작업 시작 전 `_shared/preflight.md`의 CHARTER_CHECK를 출력한다.

## 분석 영역

### 1. 누락 요구사항
- PRD/Plan 대비 미구현 항목
- 암묵적 요구사항 (에러 처리, 타임아웃, 재시도, 부분 실패 처리)

### 2. 엣지케이스
- Null/Empty 처리 (이슈 0건, 본문 없는 이슈, diff 빈 결과)
- 경계값 (레이트리밋 잔여 0, 재시도 상한 도달, 타임아웃 직전)
- 동시성 (같은 저장소 동시 스캔, 같은 후보 중복 구현 요청)
- 상태 전이 (종단 상태 재진입, 중간 실패 후 재시도 시 상태)
- 멱등성 (스캔 재실행이 후보를 중복 생성하지 않는가)

### 3. 안전 경계 누락 🔴

이 변경이 [`safety-boundaries.md`](../rules/context/safety-boundaries.md)의 방어를
**우회하거나 약화시키는 곳**이 있는지 조항별로 본다. 「위반했는가」가 아니라 **「우회 경로가 생겼는가」**를 묻는다.

| 조항 | 묻는 것 |
|---|---|
| S-1 | 이 변경으로 upstream 좌표가 push 경로에 도달할 수 있는 새 경로가 생겼는가 · Fork owner 어설션이 우회되는 분기가 있는가 |
| S-2 | draft 플래그가 설정·파라미터·분기로 뒤집힐 수 있는가 · 머지/ready/리뷰어 API가 새로 닿는가 |
| S-3 | 대상 저장소 코드가 샌드박스를 거치지 않고 실행될 수 있는 경로가 생겼는가 · 호스트 자원이 컨테이너에 새로 노출되는가 |
| S-4 | 새로 추가된 로그·프롬프트·에러 메시지·PR 본문에 시크릿이 흘러들 수 있는가 |
| S-5 | `RepositoryPolicy` 없이 다음 단계로 넘어가는 분기가 생겼는가 · 파싱 실패가 「허용」으로 처리되는가 |
| S-6 | 사람 승인 없이 파이프라인이 끝까지 흐르는 경로가 생겼는가 · 재시도 상한·종단 상태가 우회 가능한가 |

### 4. "하지 말아야 할 것" (Anti-Requirements)
- 기존 기능을 깨뜨리는 변경
- 성능 저하 (N+1 쿼리, 불필요한 대외 호출, 저장소 전체를 LLM에 투입)
- 비용 증가 (토큰 미기록, 재시도 루프 확대)

### 5. 변경 용이성 평가
- Lock-in 위험 (특정 GitHub 라이브러리·LLM 제공자에 강결합)
- 가역성 (롤백 가능한가)
- 더 단순한 대안은 없는가

## 결과 형식

```markdown
### 안전 경계 누락
| 조항 | 우회 경로 | 위치 | 설명 |
|---|---|---|---|

### Anti-Requirements

|---|------|------|

### 권장 사항

```
