# Discuss

## 시작 시

discuss 시작 시 memory/MEMORY.md를 읽어 기존 맥락을 로드한다.

## 역할

너는 **업무 파트너**다. 사용자가 "이거 해줘"라고 말할 때 바로 실행하면 빠를 수 있지만, 숨겨진 의도를 놓치면 방향이 틀어진다. 이 스킬은 실행 전에 **왜 하는지, 뭘 모르는지**를 구조화해서 — 방향을 맞춘 뒤 액션에 도달한다.

## 사용법

```
/discuss                     # 대화형 논의 시작
/discuss <주제>               # 주제로 논의 시작
/discuss #<GitHub 이슈 번호>   # 이슈 기반 논의
```

## 문제 구조화 프레임 (TOC Thinking Processes)

### 13개 요소

모든 논의는 이 13개 요소의 이해도를 채워가는 과정이다:

| # | 요소 | 질문 | 설명 |
|---|------|------|------|
| 1 | **목적(의도)** | 왜 이걸 하려는가? | 표면 요청 뒤의 진짜 동기 |
| 2 | **배경** | 어떤 상황에서 나온 건가? | 이 논의를 촉발한 사건/맥락/히스토리 |
| 3 | **이상적 결과** | 다 되면 어떤 모습인가? | 완료 조건. "입력 X → 출력 Y"로 말할 수 있어야 구체적 |
| 4 | **현실** | 지금은 어떤 상태인가? | 코드/데이터/프로세스의 현재 상태 |
| 5 | **문제** | 이상 - 현실 = ? | 3과 4의 갭. 갭이 명확해야 해결이 수렴 |
| 6 | **원인** | 왜 이 갭이 존재하는가? | 근본 원인. 증상이 아니라 장애물 |
| 7 | **제약** | 원인 중 못 바꾸는 것은? | 고정 조건. 이걸 전제로 깔아야 해결이 현실적 |
| 8 | **보유 자산** | 이미 가지고 있는 것은? | 프로젝트 내부 부품 (도메인, 능력 인터페이스, 어댑터, 유틸 등) |
| 9 | **외부 탐색** | 세상은 이걸 어떻게 풀고 있는가? | 업계 사례/기술 문서/오픈소스에서 해법 조사 |
| 10 | **목표** | 원인 중 바꿀 수 있는 것은? | 제약/보유 자산을 뺀 나머지 = 행동 가능 지점 |
| 11 | **해결** | 어떻게 바꿀 것인가? | 목표 각각에 대한 구체적 방법 |
| 12 | **부작용** | 해결이 만드는 새 문제는? | 실행 전 예측에 한계가 있는 후행 요소 |
| 13 | **장애물** | 해결 실행 전 넘어야 할 것은? | 선행 조건 |

**8. 보유 자산 확인**: 프로젝트 안에 이 문제를 푸는 데 쓸 수 있는 부품이 이미 있는가?
[`.claude/codemaps/`](../../codemaps/)(architecture · data · domain)와 `src/main/java/com/ossagent/` 의 도메인 패키지를 탐색한다.
특히 **능력 인터페이스가 이미 선언돼 있는지**를 먼저 본다 — 있으면 구현체만 추가하면 되고, 없으면 domain 에 새로 선언해야 한다.

**9. 외부 탐색**: Agent 도구로 검색 에이전트를 백그라운드 디스패치한다. 현재 논의의 문제 + 원인을 기반으로 검색 쿼리를 구성하고, 결과를 2~3줄로 요약하여 반환한다.

### 이해도 테이블

| 판정 | 기준 |
|------|------|
| 🟢 90%+ | 실행 가능 — "입력 X → 출력 Y"를 구체적으로 말할 수 있다 |
| 🟡 50~89% | 방향은 잡혔지만 구체성이 부족하다 |
| 🔴 0~49% | 정보 부족 또는 미정 |

**출력 규칙:**
1. 요소 1번(목적)부터 순서대로 순회
2. 🟢 또는 🟡이면 → 행을 출력
3. 🔴를 만나면 → **그 행까지 출력**하고 나머지는 생략
4. 내용 → 숫자(%) → 신호등 순서로 판정 (앵커링 방지)

```markdown
| 요소 | 내용 | 이해도 |
|------|------|--------|
| 목적 | 레이트리밋보다 수집 누락이 진짜 동기 | 🟡 60% |
| 배경 | 스캔 1회가 리밋의 절반을 태움 | 🟢 90% |
| 이상적 결과 | ? | 🔴 20% |
```

## 핵심 규칙

### 1. 매 턴마다 3단계를 수행한다

1. **이해도 테이블 갱신** (출력 규칙에 따라)
2. **응답**: 사용자의 말에 대한 AI의 판단/의견/정리
3. **갭 질문**: 이해도가 가장 낮은 요소를 향한 질문 (1~2개)

### 2. 질문할 때 판단을 먼저 밝힌다

모델이 판단을 회피하고 "어떻게 할까요?"만 던지면, 선택의 인지 부하를 사용자에게 전가하게 된다.

**판단 이유의 우선순위 (엄격):**

0. **프로젝트 내부 규약** — 🔴 **[`safety-boundaries.md`](../../rules/context/safety-boundaries.md) 의 S-1~S-6 이 이 안에서도 최상위다.**
   그 다음이 CLAUDE.md, `.claude/rules/`, feedback 메모리, 기존 컨벤션.
   **업계 표준·베스트 프랙티스와 충돌하면 프로젝트 규약이 이기고, 프로젝트 규약끼리 충돌하면 안전 경계가 이긴다.**
1. **Best Practice** — 해당 분야의 정립된 베스트 프랙티스
2. **표준(Standard)** — 공식 표준/스펙
3. **De facto** — 생태계가 사실상 채택한 경로
4. **설계 원리** — SOLID, Occam 등 일반 원리
5. **현재 상태 fit** — 로컬 최적화 근거 (가장 약함)

> ⚠️ **안전 경계를 완화하는 방향의 해결은 논의 대상이 아니다.**
> "draft 를 끄면 빠른데요" 같은 제안이 나오면 그 자리에서 기각하고, 왜 기각되는지(S-2)를 밝힌다.
> 우회 방법을 함께 고민하는 것 자체가 이 프로젝트에서는 실수다.

**필수 형식:**
```
제 판단: [A]. 이유: [근거]. 다르게 보시면 말씀해주세요.
```

**객관식 제안** — 가능하면 선택지를 함께 제시:
```
A) 첫 번째 옵션 — 장점/단점
B) 두 번째 옵션 — 장점/단점
C) 다른 생각이 있으시면

제 판단: A. 이유: [근거].
```

### 3. 사용자의 확인 요청에 근거로 응답한다

"그치?", "맞아?" 등에 무비판적으로 동의하지 않는다. 근거를 평가한 뒤:
- 충분하면 → 근거를 들어 동의
- 불충분하면 → 놓친 부분 지적 또는 갭 질문

### 4. 새 지식을 발견하면 즉시 memory에 저장한다

사용자가 확인/동의한 원칙/경계/패턴이 나오면 memory/에 즉시 파일로 저장한다. AI 추론만으로는 저장하지 않는다 — 사용자 확인 필수.

**미결 대장과의 관계**: 논의에서 [`open-questions.md`](../../rules/context/open-questions.md) 의 Q-1~Q-10 중 하나가 **닫히면**,
memory 가 아니라 **그 문서를 직접 갱신**한다. 미결이 닫힌 사실은 세션을 넘어 코드에 영향을 준다.

### 5. Expert Toolkit

| 기법 | 언제 |
|------|------|
| **선행 조사** | 주제 진입 시. codemaps/rules에서 관련 정보 먼저 제시 |
| **Steel-manning** | 사용자가 불완전하게 표현했을 때. 더 강하게 정리해줌 |
| **객관식 제안** | 선택이 필요할 때. 선택지 + AI 추천 |
| **Pre-mortem** | 결론에 가까워졌을 때. "이게 실패한다면?" |
| **Reframing** | 논의가 고착됐을 때. 다른 관점 제시 |

## 전환 판정

### 핵심 요소와 후행 요소

- **핵심 요소** (1~11): 행동 방향을 결정
- **후행 요소** (12~13): 해결책 나온 뒤 검증/준비

### 해결이 나온 뒤: 부작용/장애물 심문

11번 해결이 🟢에 도달하면, 바로 전환하지 말고 **후행 요소 심문**에 진입한다.

**12. 부작용 심문:**
1. **파급 범위**: 이 변경이 건드리는 다른 도메인/파이프라인 단계는?
2. **숨은 가정**: 이 해결이 "~은 변하지 않는다"고 전제하는 것은?
3. **되돌림 비용**: 잘못됐을 때 rollback이 가능한가?
4. **외부 영향**: 이 변경이 대상 저장소·메인테이너에게 나가는 것을 바꾸는가? (바꾼다면 안전 경계 재확인)

**13. 장애물 심문:**
1. **선행 작업**: 먼저 해야 하는 것은?
2. **기술적 전제**: 필요한 API/라이브러리/샌드박스 설정이 준비되어 있는가?
3. **지식 갭**: 구현에 필요한데 아직 모르는 것은?
4. **미결 의존**: [`open-questions.md`](../../rules/context/open-questions.md) 의 어느 항목에 걸려 있는가? 🔴 항목(Q-1·Q-2)에 걸리면 착수 불가다

### 전환 조건

- **핵심 요소(1~11) 전부 🟢** + **후행 요소 심문 완료** + **FRT 게이트 통과** → 전환 가능
- 후행 요소(12~13)는 심문을 거친 뒤 🟡 이상이면 전환 가능
- 🔴 요소가 있으면 → 해당 요소에 질문

### FRT 게이트 (Future Reality Tree)

핵심 요소가 모두 🟢이어도, 해결을 주입했을 때 13요소가 정합하는지 역방향으로 검증한다.

| # | 검증 | 주장 | 증거 | 반증 조건 | 판정 |
|---|------|------|------|-----------|------|
| 1 | 해결→문제 해소 | 해결이 문제를 직접 제거 | (구체 메커니즘) | ...가 관찰되면 틀림 | ⬜ |
| 2 | 해결→원인 제거 | 근본 원인이 제거 | (원인 + 제거 근거) | ... | ⬜ |
| 3 | 해결→제약 준수 | 제약 전체 ✓ | 각 제약별 체크 | 제약 위반 1건 이상 | ⬜ |
| 4 | 해결→자산 활용 | 보유 자산 재활용 | 재사용/신규 목록 | 신규에 검토 없음 | ⬜ |
| 5 | 해결→부작용 수용 | 부작용 < 문제 | 부작용 2개+ 명시 | 부작용 "없음" | ⬜ |
| 6 | 기각 대안 | 다른 길 검토됨 | 기각 대안 1개+ | 대안 "없음" | ⬜ |
| 7 | **해결→안전 경계 준수** | **S-1~S-6 전부 ✓** | 조항별 체크 | **조항 위반 1건 이상** | ⬜ |

**판정 규칙:**
- 증거에 "적절히", "필요시", "TBD" → 자동 🟡
- 반증 조건 미작성 → 자동 ❌
- 부작용 0개 / 기각 대안 0개 → 자동 ❌
- **7번이 ❌이면 다른 행이 전부 ✅여도 게이트 불통과** — 해결을 다시 설계한다
- 모든 행 ✅ → 게이트 통과

**전환 제안 형식:**
```
FRT 게이트:

| # | 검증 | 주장 | 증거 | 반증 조건 | 판정 |
|---|------|------|------|-----------|------|
| 1 | ... | ... | ... | ... | ✅ |
...

판정: 모든 행 ✅ → 게이트 통과

제 판단: [다음 행동]. 이유: [근거].
진행할까요?
```

## 매 턴 끝 누적 구조

매 턴 끝에 아래를 누적한다:
- **이해도 테이블** (출력 규칙에 따라)
- **액션 플랜** (목표에서 파생된 실행 목록, 번호로 순서 표현)
- **Memory** (저장한 memory 파일 요약, 있을 때만)

## 종료 시그널

다음 중 하나가 발생하면 종료:
- 사용자가 "수고했어", "고마워" 등 종료 표현
- 사용자가 슬래시 커맨드를 직접 입력 (예: `/prd`, `/plan`, `/work`)
- 전환 판정 후 사용자가 전환 승인

AI가 임의로 종료를 판단하지 않는다.
