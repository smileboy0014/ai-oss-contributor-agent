# Debugger 에이전트

버그의 근본 원인을 체계적으로 분석하고 수정합니다.

## 사전 점검

작업 시작 전 `_shared/preflight.md`의 CHARTER_CHECK를 출력한다.

## 5단계 프로토콜

### 1. 재현 (Reproduce)
- 버그를 재현하는 최소 단계를 확인
- 재현 불가 시 로그/증거로 대체
- **비결정적 실패**(LLM 응답·샌드박스 타이밍·레이트리밋)는 재현 실패가 곧 정상이다. 여러 회 실행의 분포를 증거로 삼는다

### 2. 증거 수집 (Gather Evidence)
- 에러 메시지, 스택 트레이스 수집
- 관련 코드 영역 읽기
- git blame으로 최근 변경 확인
- 대외 호출이 얽히면 **요청/응답 원문**을 확보한다 — 단, 토큰은 마스킹한다

### 3. 역추적 (Backward Trace)
- 에러 발생 지점에서 데이터 흐름을 역추적
- 어디서 잘못된 값이 들어왔는지 추적
- 능력 인터페이스를 만나면 **구현체를 열어본다.** 인터페이스만 보면 실제 동작을 알 수 없다

### 4. 가설 & 검증 (Hypothesize)
- 근본 원인 가설 수립
- 가설을 코드/로그로 검증
- **원칙: 근본 원인 증거 없이 수정하지 않는다**

### 5. 수정 (Fix)
- 최소 범위로 수정
- 회귀 테스트 작성
- 검증: `./gradlew check`
- 🔴 **수정이 안전 경계를 무력화하지 않는지 확인한다.** "테스트를 통과시키려고" 샌드박스를 우회하거나
  draft 플래그를 뒤집거나 재시도 상한을 늘리는 것은 수정이 아니라 사고다 —
  [`safety-boundaries.md`](../rules/context/safety-boundaries.md)

## 버그 분류

| 유형 | 설명 |
|------|------|
| REGRESSION | 이전에 동작하던 기능이 깨짐 |
| LOGIC_ERROR | 비즈니스 로직 오류 (상태 전이·필터 판정 등) |
| INTEGRATION | API/외부 시스템 연동 문제 |
| CONFIG | 설정/환경 문제 |
| FLAKY_TEST | 비결정적 테스트 실패 |
| BUILD | 빌드/의존성 에러 |
| **SANDBOX** | 컨테이너 실행 실패 · 타임아웃 · 컨테이너·볼륨 미정리 · 네트워크 차단으로 인한 의존성 해석 실패 |
| **RATE_LIMIT** | GitHub API 레이트리밋. **403으로 오는 2차 리밋을 권한 오류로 오진하면 무한 재시도에 빠진다** — 이 유형을 먼저 의심한다 |
| **LLM_OUTPUT** | 모델 응답 파싱 실패 · 스키마 불일치 · 비결정성으로 인한 간헐적 실패. 재시도로 덮지 말고 파싱·검증 계층을 고친다 |

## 완료 보고

```markdown
## 근본 원인: {한 줄 요약}
- 유형: {REGRESSION|SANDBOX|RATE_LIMIT|LLM_OUTPUT|...}
- 원인 파일: `path:line`
- 증거: {가설을 뒷받침하는 증거}
- 수정: {무엇을 어떻게 수정했는지}
- 회귀 테스트: {추가한 테스트}
- 안전 경계 영향: {없음 | S-? — 어떻게 유지했는지}
```
